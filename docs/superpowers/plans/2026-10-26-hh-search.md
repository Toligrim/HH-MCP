# HH-MCP bounded search engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement stages 0–3 of issue #1 through Luna 6 workers and independent reviews.
**Architecture:** Keep the application in candidate-source/, with pure search modules behind the existing hhGet gateway. Quick search stays compatible; deep MCP is bounded and stateless, local operator CLI explicitly owns persisted checkpoints.
**Tech Stack:** TypeScript, Node >=18, Zod 3, MCP SDK, Vitest. No new runtime dependencies.
**Spec:** docs/superpowers/specs/2026-10-26-hh-search-design.md; full issue /tmp/hh-mcp-issue-1.md.

## Global Constraints
- Product root is candidate-source/; preserve ops history, SOURCE-CANDIDATE.txt baseline, MIT attribution and original source checkout.
- No GitHub Actions, service/network/proxy/auth/env changes, publishing, pushing, merging or deployment.
- All new HH reads use hhGet and its shared limiter. No arbitrary remote URL, file path, protected employer/resume endpoint, token forwarding or secret/body disclosure.
- Preserve old tool names, default per_page=20 and raw:true exact HH JSON. New unknown criteria must be rejected or explicitly reported.
- New MCP deep call caps: 20 seconds, 25 HTTP attempts, 500 items, 2 MiB received, 64 KiB output, top 20.
- CLI defaults: 600 seconds, 500 attempts, 20,000 items, 64 MiB; hard caps 1,800 seconds, 1,000 attempts, 50,000 items, 128 MiB. Per-process limiter; multiprocess jobs unsupported.
- export_enabled=false, bulk_jobs_enabled=false; no server jobs/downloads/cursors whose identity scoping is unresolved.
- All descriptions untrusted. Missing data is unknown. Coverage never means all historical HH data.
- TDD for behavior changes, focused tests while iterating, full npm test + typecheck/lint before commit. Record RED/GREEN evidence.
- No subagents inside workers or reviewers. One implementation task at a time.

## Review Focus
- SDK raw .shape validation must not lose cross-field rules or silently drop unknown keys: registered MCP transport tests in Task 5, handler reparse in Task 2.
- Dates round to five minutes; overlapping split boundaries must progress and never pretend unspecified inclusivity is proven: Task 4 fixtures.
- Retries, limiter queues and response bodies must respect shared deadlines and actual-attempt/byte budgets: Task 1 tests.
- A forbidden card or ambiguous text must not become a positive match or leak upstream error bodies: Task 3 tests.
- Resume must bind checkpoint to exact normalized query/limits/version and preserve dedup/provenance/counters: Task 4/5 tests.
